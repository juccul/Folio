# Development status — Folio 0.1.1

Updated 2026-10-07. Folio is a runnable Rust/GPUI Linux desktop application. Production certification still requires physical tablets and additional desktop/distribution sessions; synthetic events and CPU benchmarks do not establish hardware-to-display latency.

Version 0.1.1 adds Windows 11 x64 builds, a portable package and a per-user installer. See `WINDOWS.md` for Windows Ink support and validation limits. The earlier public version reset was 0.1.0. Historical sections below retain their original internal development build numbers. This release includes Vulkan Q8 OCR with verified first-use downloads, along with test and runtime-payload cleanup.

## Continuous integration

The `Linux and Windows` workflow tests every branch push, pull request and tag,
and can be started manually with `workflow_dispatch`.
New pushes cancel superseded runs on the same branch,
and pull request updates cancel superseded runs for that pull request. Release
tag builds and manually started builds are not cancelled by branch updates.

Rust tests run with two test threads in CI to limit contention between each
controller's storage and rendering workers. Asynchronous worker behavior remains
covered. To use the same limit locally, run
`cargo test --locked --workspace -- --test-threads=2` on Linux or
`./scripts/build-windows.ps1 -Test -TestThreads 2` on Windows. Omitting
`-TestThreads` preserves Cargo's default parallelism for local Windows builds.
Updater, packaging, math protocol and Rust checks have separate CI steps so the
failing check is visible directly in the run summary.

## Application title bar

Folio requests client decorations and uses the document tab strip as its title bar. The + picker follows the last tab; tabs scroll when space runs out, while the picker stays visible and minimize, maximize/restore and close stay at the far right. Empty-space presses start compositor-driven movement; double-click toggles maximize and right-click opens the native window menu. Tabs consume their own presses and retain drag reordering. Edge/corner hitboxes resize floating windows and are omitted on maximized/fullscreen or tiled edges. The library shows the same title bar without changing the open-tab list. Dialogs occupy the area below it, and window controls remain accessible during overlays and document loading. Close explicitly flushes pending note changes and reports failure instead of removing the window.

The vendored X11 backend now allows opaque client frames without a compositor or GTK frame-extents support; transparent frames retain the existing server-decoration fallback. Verification is recorded under `artifacts/validation/titlebar`, including private Mutter/Xwayland window movement, tab reordering, controls and resize, native Wayland controls, and existing pen/navigation and solver regressions. No physical desktop or tablet is controlled by these tests.

The earlier title-bar release passed 90 focused Rust tests, strict all-targets Clippy and formatting, 13 Mutter/Xwayland title-bar checks, seven native Wayland checks, 33 solver/graph/editor regressions, and the native pen/navigation/tab-reordering smoke replay. ## Explicit offline recognition, copy and replacement — current implementation

Selected visible strokes use one resident GLM-OCR model for both text and math. The GPUI toolbar starts a bounded asynchronous worker. Text renders the whole selection to preserve paragraph layout; formula rendering preserves numerator/denominator and script geometry. Official task prompts select text or formula recognition. The worker uses native Transformers, BF16, SDPA, greedy decoding and KV caching; switching tasks retains the same model. CPU PyTorch defaults to four threads. The JSON-lines protocol blocks internet sockets, disables Hub access and remote code, has a 180-second response timeout, and kills the process on cancellation/app shutdown. Linux parent-death handling covers unexpected app exits. Token-cap hits fail with a smaller-selection message rather than returning partial text. Math strips outer display wrappers without rewriting operators or grouping. The legacy Python recognition path never downloads models. The native Q8 path downloads verified model/runtime assets on first use, as described in README.md and OCR_FIRST_USE.md.

The result opens an editable multiline review. Copy text puts the corrected full result on the native clipboard without a document edit. Replace writing removes only the captured strokes and adds editable content at their original bounds in one journaled command: a TextBlock for text or a rendered Equation for math. Math replacement validates and renders the corrected LaTeX on the document worker before changing the page; failure restores the corrected review and retains the ink. Captured objects are checked against the current note/page/source before accepting a result and again before replacement, including after asynchronous equation rendering. Generations discard cancelled responses. Original sensor data stays in undo history and durable recovery. Recognition remains explicit.

`scripts/setup-recognition.py` verifies all pinned GLM checkpoint, processor, tokenizer and model-card hashes. `--copy-model` creates a portable model directory; otherwise both tasks reference the same local files. Setup retains attribution and the model card's MIT declaration, records runtime versions and atomically publishes the configuration. No GLM SDK, layout detector, IAM or MathWriting dataset is bundled. The current pack at `artifacts/recognition-v2` uses the CPU-only runtime and the benchmarked GLM revision. Older local model files are retained for benchmark reproducibility, but the configured worker no longer loads ConvText or Qwen.

The historical GLM benchmark recorded 400 offline scored predictions: CPU text nonspace CER 3.32% at 2.36 seconds median, and format-normalized math matches 30/100 at 1.91 seconds median. This supports a user-selected shared-model configuration, with lower formula accuracy than the earlier Qwen experiment and higher cost than ConvText previews. The app's whole-selection stroke rendering and four-thread runtime differ from the original IAM image/eight-thread benchmark, so app latency and paragraph accuracy need separate evaluation. Physical tablet accuracy remains unmeasured.

The encoding optimization replaces CUDA BF16 full-patch Conv3d with a mathematically equivalent dense projection using the same weight objects and bias. CUDA-event ablations identify this initial projection as the GPU bottleneck. On 200 new same-cohort predictions, text median is 214 ms (previously 6.03 s), math 272 ms (previously 3.17 s), text nonspace CER remains 3.39%, and formula matches are 31/100 versus 30/100. Two text and five formula outputs changed; none of the previously correct normalized examples lost correctness. Input pixels, processor, resolution, dtype, decoder and token cap match. CPU probes show negligible end-to-end benefit, so the adapter leaves CPU execution native. Four projection/fallback tests pass with CUDA, eight existing worker tests pass, and the installed four-thread worker passes text/math/text and paragraph JSON-line requests. Setup installs the helper and supports `--encoder-projection native` for reversal. An optional ready GPU pack is at `artifacts/recognition-cuda/pack.json`; the existing CPU pack remains the default.

Validation for the shared-model change covers paragraph/dot geometry, translation-invariant crops, math wrappers, single-model reuse, truncation rejection, invalid input and offline sockets. Existing controller tests cover atomic mixed-selection replacement, stale results, cancellation, raw ink and undo/redo/reopen. Eight worker tests and five recognition/controller regressions pass. Real GLM fixtures pass review/replacement/undo/redo/reopen for text and math; a two-line paragraph preserves line breaks, and switching task prompts reuses the loaded model. Native corrected-text clipboard, replace/undo/redo, math cancellation and pen/navigation smoke pass against the release app. Evidence is recorded under `artifacts/validation/glm-recognition`. Earlier validation under `artifacts/validation/recognition-v2` and the historical sections below describe previous configurations.

Rendered math replacement adds three controller regressions for corrected LaTeX, vector glyphs, neighboring object order, durable undo/redo/reopen and equation editing; invalid LaTeX preserves the corrected review and ink; moved/off-page/cancelled render results cannot replace source strokes. All eight recognition-related tests pass, along with formatting, strict app/UI all-targets Clippy and the release build. A real optimized CUDA GLM math fixture passes review/replacement/undo/redo/reopen (5.23 seconds including cold model startup). Native release-app verification checks corrected multiline text and LaTeX through the real clipboard, renders a fraction and square root, and verifies replacement undo/redo. Its screenshot was visually inspected. Evidence is under `artifacts/validation/ocr-equation`; these checks do not measure warm app latency or physical tablet input.

Optional application INT8 trials use `artifacts/recognition-cuda-int8/pack.json`. Setup accepts `--quantization int8` with bitsandbytes 0.50.2 and accelerate 1.15.0. The worker quantizes the pinned original checkpoint at loading with LLM.int8 threshold 6.0, explicitly maps the model to the configured device, verifies actual INT8 layers and rejects unintended parameter offloading. BF16 remains the default, and nonquantized layers/inputs retain BF16; CUDA's full-patch projection stays optimized. Eleven Python worker regressions pass. ## Optimization and correctness — 0.1.10

Ordinary edits update only changed spatial-index entries and the source references of derived shapes/equations. Reference counts keep an original stroke hidden when several derived objects share it, including after undo/redo. Command application no longer scans every page to restore drawing order; appended ink keeps its existing order, while insertion/deletion restoration remains exact. Session drawing-order ranks update incrementally for appended objects and are rebuilt for removals or middle insertions.

The renderer caches the ordered visible object set until the page revision, spatial-index generation or viewport changes. Completed path-cache maintenance runs when that set changes rather than on every pen frame. Ruled, grid and dotted paper share one cached compound path per viewport/theme instead of rebuilding many small paths on each redraw. Text/image/equation pixel copies and theme adaptation run on GPUI background tasks, with at most two conversions in flight. Rendering rejects stale source objects, pixels and theme results. The controller trims preview/session caches every 250 ms instead of scanning them every UI tick. Worker results are bounded to eight items rather than 64, limiting queued decoded-image accumulation; this is not a bound on total application RAM.

Preview completions/errors for edited, deleted or evicted objects are discarded. Offscreen-page results cannot insert their bounds into the active page's index. Higher-resolution previews are retained when a smaller render budget would already suffice. Repeated document-load requests are coalesced, and a failed queue submission no longer leaves a tab indefinitely pending. A failed held-pen shape fit runs once until the pen moves substantially, preventing repeated stationary fitting; endpoint tremor tolerance and continued drawing/shape recognition remain intact. Saturated grid-cell counts use checked arithmetic; extreme imported coordinates and non-finite query bounds cannot overflow the index or cause huge grid allocation.

All 122 workspace tests, formatting and strict all-targets Clippy pass. Native pen/navigation smoke, AT-SPI document management and appearance/overlay checks, headless PDF/export/search/reload checks, and actual finite-animation/idle-frame captures pass on isolated displays. Light/dark/custom-paper views were reviewed at normal and compact sizes with 160% UI scaling. A separate mixed-raster fixture verifies six 3-megapixel color images, typed text and an equation across light/dark/fixed/custom paper; all image colors remain intact after asynchronous preparation. The ordinary six-note fixture used about 191 MiB resident RAM at one snapshot; this is not a peak or large-document bound. Regression coverage includes shared derived-source visibility, mixed insertion/edit undo ordering, stale/offscreen previews, repeated loads, failed-hold recovery, large-coordinate indexing and cached paper/raster invalidation.

The same CPU benchmark before/after this pass measured command application plus spatial-index maintenance p99 at 78.3 → 4.5 μs for 10,000 strokes and 881.8 → 2.9 μs for 50,000 strokes. Initial full saves remained about 1.2 / 5.5 seconds and loads 277 / 1,369 ms respectively. Runs vary with machine load; initial 10,000-stroke checks measured update p99 near 2 μs. These improvements remove whole-page scans from this particular edit path, not all application work.

Validation and measured CPU results for this pass are recorded in `artifacts/validation/optimization`. The benchmark measures command application plus spatial-index maintenance separately from drawing, persistence and presentation; its reduction must not be read as an equivalent improvement in physical pen latency. Full-document save/load still scale with document size. No external dependency, document format, recognition component or system input configuration was added.

## Recognition removal — 0.1.8

At the user's request, handwriting OCR and text detection are removed for now. The recognition crate, text/math inference adapters, resident model processes, preprocessing functions, setup/package scripts and recognition fixtures were deleted. The geometric character/word/line/paragraph detector was also removed, including its dependent baseline/slant/height/spacing refinement, handwriting reflow, word strike-through and between-line insertion gestures. Vector smoothing/refinement, manual insertion/removal of space, scratch erase, encircle selection, shape snapping, typed text and manual LaTeX rendering remain. PDF import, image editing and notebook management are unchanged.

Existing page group records and group commands remain only for serialization/undo compatibility. Stored ink and equation sources are not discarded. Page text, export, accessibility and search no longer consume legacy recognized text. Database schema 3 rebuilds the derived FTS index from actual typed text/equation objects, titles and tags in one transaction; legacy documents and history are not rewritten. Earlier applications reject the newer schema. Old recognition fields are ignored when loading settings and omitted when saving.

Portable/RPM/Debian packaging no longer includes models, Python inference runtimes, model flags or Hunspell/Tesseract recommendations. The launcher selects native Wayland on Wayland sessions, including GNOME, and X11 on X11 sessions. Set `FOLIO_FORCE_X11=1` for a process-only X11 fallback. ## Recognition quality and review — 0.1.7 (historical; removed in 0.1.8)

Offline interactive-recognition alternatives were researched on 2026-10-04. Small MathNote/Texo candidates reduced worker memory but failed the 12-expression screening, so no application default was changed. The recommended direction is persistent stroke-linked semantic editing/corrections plus independently evaluated compact text/math engines, with on-demand large-model fallback and idle worker unloading. These additions remain development work.

Recognition uses black monoline ink on white paper, retaining transformed dots, scripts, descenders and fraction bars. Pressure/style/opacity decoration no longer degrades the OCR input; raw strokes and export rendering are untouched. Text crops preserve whole cursive words, split exceptionally long lines only at whitespace and retain line context for the trained handwriting encoder. Three deterministic beam candidates provide stored alternatives and conditional model scores. A private eight-line IAM comparison reduced character error from 5.05% to 2.45%; CPU time increased from 54 to 133 seconds for the eight-line batch including startup. This small test is not a general accuracy claim; model scores are not calibrated accuracy probabilities. Validation samples remain outside release archives.

Selected text can be recognized independently of nearby equations. New recognition replaces only groups touching that selection; unrelated recognized lines remain searchable. Results are tied to page revisions and stale jobs cannot rewrite newer ink. Each line has its own cancellable resident request and timeout, avoiding a whole-page three-minute limit. Math uses the entire selected region rather than text-line splitting. Results open an editable LaTeX review before conversion, with alternatives where the model supports them. Accepting renders on a background worker, preserves source ink and is undoable; cancellation leaves the ink alone. Invalid/stale proposals are rejected. The compatibility path still supports older MIT Pix2Text packs and custom local executables. The new pack uses the Apache-2.0 `phxember/Uni-MuMER-Qwen3-VL-2B` checkpoint at `26d57451c9182b68c60aef78634bfea20c41a866`, selected after the old model, a formula-specific ONNX model and a general-purpose vision model failed the handwritten tests. The adapter translates the checkpoint's newer processor/tokenizer/rotary configuration into the pinned runtime's schema without modifying model files. On this Ryzen 7940HS, twelve private MathWriting samples took 85 seconds and matched 9/12 references after documented LaTeX formatting aliases, versus 1/12 for the previous default. This small sample is not a benchmark claim, and visually ambiguous symbols still fail. Model scores can be high for incorrect output: review remains mandatory. Dataset files are not distributed; source/license notices and pinned model checksums are retained in the pack. Runtime inference and checksum verification are offline. A parent-death signal binds the recognizer process to Folio so model memory is released after an unexpected app exit. Rendering failures restore the edited equation proposal instead of losing corrections or rerunning recognition. The `recognition_fixture` example accepts external stroke JSON and a local pack, replays real controller pen events and checks review-before-conversion, vector rendering, raw source retention, undo/redo and durable save. ## Held pen shape recognition — 0.1.5

Normal-pen shape snapping previously depended entirely on the preview timer. Motion above 1.5 document units reset that timer, including ordinary endpoint tremor, and lifting without a preview skipped recognition. Hold detection now tolerates four screen pixels of endpoint movement independently of zoom. Pen-up repeats the fit when an endpoint has been held for at least 550 ms, even if no preview tick ran. Unheld pen strokes, disabled hold recognition and normal highlighter strokes remain freehand. The explicit Shape tool fits on lift. Existing scratch/encircle priority is preserved.

The standalone shape crate now separates resampling/geometry, polygon fitting and circular/elliptical fitting. Arc-length resampling bounds geometric fitting to 192 samples and removes sensitivity to report density or duplicate dwell points. Fits normalize position/scale, use geometric residual thresholds, tolerate rough closures and small hooks, and fit lines/rectangles in their actual orientation. The model adds open Arc and Polyline objects for circular arcs, L-shaped paths and clear angular paths. Clear L-shaped paths snap to a right angle rather than retaining a small extra bend. Curves and generic paths remain open unless their geometry supports closure. No model, SDK or external dependency was added; all fitting code is original GPL-3.0-or-later Rust. Snapped shapes, their live previews and page thumbnails use the ink engine's round compound outlines with NonZero fill. This avoids GPUI stroke-join taper artifacts where an arrowhead retraces its tip; completed shape geometry stays cached.

Arrows accept shaft-first or head-first single traces and two separate traces without manufacturing a connector between them. A two-stroke arrow requires explicit shape intent on the second trace, a nearby matching preset, geometric agreement and a source started within five seconds. It retains both raw strokes as independent source objects. Replacing a previously snapped shaft is one command; undo restores the previous line and redo restores the arrow. Moved/transformed, old, unrelated and differently styled ink is excluded.

Synthetic regression traces follow the reported rough rectangle, triangle, curved line, open arc, L, crossing angular path, circle with closing hook and arrow. Controller tests cover endpoint tremor at several zoom levels, missed preview ticks, disabled settings/highlighter behavior, source preservation, undo/redo, save/load and join boundaries. The `shape_fixture` example drives normal pen input with real 650 ms holds into throwaway notes and asserts the resulting shape kinds. Validation logs and native captures are in `artifacts/validation/shapes`. These approximate screenshot geometry rather than recorded tablet sensor input; physical tablet recognition recall remains unmeasured. ## Overlap rendering and gesture recall — 0.1.4

Pressure outlines folded over themselves at acute reversals, and GPUI's default even-odd fill cut holes through overlapping ink. Rendering now splits tight turns/cusps into round contours with consistent winding and fills the compound path using NonZero. SVG/PNG/PDF use the same geometry and fill rule. Opaque active ink retains cached 256-point chunks; translucent active ink composites the whole compound stroke once to avoid darker self-crossings. Completed stroke geometry remains cached. GPUI tessellation indices are now 32-bit to avoid silently dropping complex paths above 65,535 vertices.

A render-only simplifier bounds combined centerline/radius error to at most 0.03 document units, with tighter tolerance for fine pens. It runs in blocks of at most 256 segments; every original processed and raw sample stays in the document. This reduces tessellation cost without changing stroke editing, recognition, erasing or recovery data. Extremely long translucent strokes still require whole-path tessellation each frame; this is a remaining performance limitation. The reproducible `folio-ui` example `ink_geometry` measures actual GPUI CPU tessellation without a display or input devices. Its release results are in `artifacts/validation/ink-gestures/tessellation.log`; they exclude GPU/compositor/physical pen latency.

Scratch recognition accepts three broad passes in a narrow corridor, uneven reversals, and wider repeated loops that revisit the same area. Wide W/M-like advancing strokes remain rejected. After validating the gesture, every real crossed ink stroke is targeted; requiring three crossings per letter caused missed edges and crossbars. Small disconnected i/j dots and t bars attach only to a nearby crossed substantive letter by geometry. This does not recursively expand through words/lines or erase objects merely because their boxes overlap. Text/images/equations stay excluded. Erasing remains one reversible command and keeps raw source data available through undo.

Encircle selection is transient: contact inside the selected bounds or a resize/rotation handle edits the selection; the first outside contact clears it and starts a pen stroke with that very first sensor sample. The chosen pen style stays intact. Explicit Lasso/rectangle selection, Select All and pasted selections remain persistent. Changing notes/pages resets the transient mode. Gesture opt-in settings remain unchanged.

Regression tests cover overlap alpha and missing pixels at acute/retraced/crossed paths, same contour winding, render simplification error, large GPUI paths, short/uneven/circular scratches, attached versus neighboring dots, one-command erase/undo, first outside pen sample, explicit lasso persistence and selection handles/navigation. Native verification uses an isolated Xvfb/D-Bus session and throwaway notes; no live tablet, Bluetooth state, compositor or desktop settings are touched. All 82 workspace tests, strict Clippy, formatting, native smoke replay and native accessibility actions pass. Release CPU geometry/tessellation medians are 0.047 ms for 256 points and 6.105 ms for 12,000 points. ## Gesture reliability — 0.1.3

Scratch erase previously required at least six horizontal passes, a 30-unit-wide footprint and two separate objects. That rejected short or angled scribbles and single-stroke cursive writing. The recognizer now samples by traveled distance, finds the principal drawing direction, and counts broad reversals with distance hysteresis. Four passes suffice for a narrow scratch; compact multidirectional scribbles require five. A candidate must cross the actual vector geometry at least three times. The controller queries the spatial index and can erase one stroke or a handwriting-derived shape; images, typed text and clean equation objects are excluded. Deletion remains one reversible command, including shape source strokes. A scribble that finds no valid target remains ink.

Encircle selection now checks winding and area in the loop's principal coordinate frame, tolerates a modest endpoint gap or overrun, and trims an overdrawn tail before polygon containment. Geometry is independent of report density and circle/oval orientation. Enclosed objects are tested against their transformed paths or rectangle outlines; a long crossing stroke is not selected merely because its bounding-box center is inside. At least 90% of sampled geometry must be inside or within two document units of the boundary. These are deterministic approximations, not handwriting intent recognition.

A successful encircle activates the lasso for immediate move/resize/rotate; press P or choose Pen to resume writing. Holding the end of an encircle does not let a shape preview override a valid selection. Explicit Shape mode and highlighter strokes bypass these smart pen gestures. Pen-up positions now finish move, resize, rotation and manual lasso interactions, including a quick drag with no intermediate motion frame. Raw stroke points remain unchanged. Gesture toggles retain their existing opt-in defaults.

Regression coverage includes sparse/dense samples, horizontal/vertical/diagonal scratches, ordinary writing and jitter rejection, real segment intersections, gapped/overdrawn/rotated/clockwise ovals, enclosure versus crossing ink, single-stroke erase, neighboring ink/text preservation, undo/redo/reload, immediate selection dragging, held endpoints and explicit highlighter/shape behavior. All 73 workspace tests and strict Clippy pass. Logs are in `artifacts/validation/gestures`. These synthetic datasets address the reported missed triggers; physical pen recordings and a broader handwriting corpus are still needed to tune recall and false positives across users.

## Architecture

The workspace separates `apps/desktop` and `app`, `ui`, `input`, `ink`, `canvas`, `document`, `storage`, `gestures`, `shapes`, `math`, `pdf`, `search`, `export`, and `platform` crates. Rust 1.92+ is required by the subset-font PDF backend. Ink, geometry and structured documents have no GPUI dependency. The UI forwards operations to a controller; document mutation and LaTeX rendering are outside the presentation layer. Explicit optional recognition lives in `app::recognition` and a resident local Python worker; no automatic text detector is present.

Native Linux GPUI patches provide Wayland tablet-v2 frames, tablet pads and pointer pinch gestures, and XInput2 pressure/tilt. Six pen styles share an incremental pressure/velocity filter and vector outlines. Raw and processed vectors are shared immutable arrays so transformations and undo do not copy sensor buffers. Raw samples survive smoothing, transforms, segment erasing, shape/equation conversion and refinement. Each erased fragment keeps original sensor samples plus an independent visible path.

Completed paths are cached; opaque active ink is divided into 256-point chunks with a bounded mutable tail. Translucent active ink uses one compound fill for consistent overlap opacity. A uniform-grid spatial index updates changed objects and derived-source reference counts and culls offscreen content. Visible objects are cached in document order until their revision, index generation or viewport changes. Paper geometry is also cached. Images, text and equations use bounded worker-generated previews; GPUI transforms those raster sprites on the GPU, keeping them aligned with vector ink during pan, zoom, resize and rotation.

Message-passing workers separate persistence, document/rendering processing and search/load. Each expensive processing queue holds at most 16 jobs; the result channel holds eight items. GPUI pixel preparation has a separate two-task bound. Search generations coalesce obsolete search jobs. Persistence uses a 64-item channel; saturation or disk errors retain the live document and bounded command history for a full retry rather than blocking pen input or accumulating failed deltas indefinitely.

## Persistence and recovery

SQLite uses WAL, `synchronous=FULL`, foreign keys, stable UUIDs, per-object rows and atomic document/search/journal transactions. Schema version 6 adds an indexed, stable page-to-FTS-row mapping independent of SQLite page rowids, plus note/page-position and draft indexes. Every writer open upgrades older databases transactionally; versions 3–5 retain their existing valid FTS rows, while older databases first rebuild legacy OCR search content. Earlier builds reject schema 6. Search updates use rowid lookups and skip unchanged content. Document format 3 adds optional math links to the version 2 cut-path and character-group records; version 1/2 documents remain readable. Editing upgrades the format, and clipboard writes use V2 while accepting V1. Each history holds at most 512 commands; full catch-up saves replace its journal consistently with the current live state.

Normal edits write changed objects and affected page headers/FTS rows. Metadata-only edits update searchable titles/tags without rebuilding every page. Active ink drafts are saved approximately once per second. Completion clears the draft in the stroke transaction. Periodic SQLite snapshots retain three generations. Assets must be backed up with the database.

Recovery never overwrites or renames the original data. It prefers a healthy checkpoint, otherwise salvages independently readable records into a new sibling directory, copies assets, and writes `RECOVERY.json` with issues. Asset maintenance considers current documents, undo history and retained snapshots and moves unused files to `orphaned-assets`; it does not permanently delete them. Damaged snapshots stop maintenance rather than guessing references. Save errors remain visible and retry from the retained live document.
